
# 🏗️ Architecture

Central de estudos, referências e práticas relacionadas à **Arquitetura de Software**.

Esta seção reúne conceitos e abordagens utilizados para projetar sistemas organizados, desacoplados, evolutivos, resilientes e escaláveis.

---

## 🗺️ Conteúdos

### 📐 System Design

Conceitos e práticas para projetar sistemas considerando requisitos funcionais e não funcionais.

* Requirements
* Scalability
* Availability
* Reliability
* Performance
* Capacity Planning
* Resilience
* Trade-offs

→ [Acessar System Design](./system-design/README.md)

---

### 🧱 Clean Architecture

Princípios para estruturar sistemas com baixo acoplamento e separação clara de responsabilidades.

* Entities
* Use Cases
* Interface Adapters
* Infrastructure
* Dependency Rule
* Dependency Inversion
* Boundaries
* Separation of Concerns

→ [Acessar Clean Architecture](./clean-architecture/README.md)

---

### 🧠 Domain-Driven Design

Abordagem para modelagem de software orientada ao domínio do negócio.

* Domain
* Entity
* Value Object
* Aggregate
* Repository
* Domain Service
* Application Service
* Bounded Context
* Ubiquitous Language
* Domain Events

→ [Acessar DDD](./ddd/README.md)

---

### 🔗 Microservices

Conceitos e práticas relacionados à construção e evolução de sistemas baseados em serviços independentes.

* Service Boundaries
* Service Communication
* Service Discovery
* Configuration
* Data Ownership
* Resilience
* Scalability
* Deployment
* Observability

→ [Acessar Microservices](./microservices/README.md)

---

### ⚡ Event-Driven Architecture

Arquiteturas baseadas em eventos para comunicação assíncrona e desacoplamento entre componentes e serviços.

* Events
* Producers
* Consumers
* Event Brokers
* Event Streaming
* Eventual Consistency
* Event Sourcing
* CQRS
* Message-Driven Architecture

→ [Acessar Event-Driven Architecture](./event-driven/README.md)

## 🎯 Objetivos

Esta seção tem como objetivos:

* compreender diferentes estilos arquiteturais;
* estudar padrões de arquitetura e design;
* analisar trade-offs técnicos;
* documentar decisões arquiteturais;
* conectar teoria e implementação;
* aplicar conceitos em projetos reais;
* evoluir gradualmente a complexidade dos sistemas.
